Schlange

An open-source, self-hosted merge queue that reads your existing .mergify.yml, so main stays green.

Early development · not production ready
Source on GitHub Implementation status

Why a merge queue

Two pull requests can each pass CI and still break main together. A merge queue tests every change on top of the current main and the changes ahead of it, and lands it only if that exact combination is green.

Schlange (German for snake and for queue) does this as a drop-in for Mergify's merge queue, built first for one real project whose configuration must keep working unchanged.

What it aims for

Your configuration, unchanged

Reads .mergify.yml: queue rules, two-step CI, batches, bisection, commands and their restrictions.

Runs where you run

One static binary in a FROM scratch image of about 10 MB. Read-only, no shell, no git, SQLite on one volume.

Explains itself

schlange explain shows why a pull request waits, condition by condition. Every merge leaves an audit record.

Made for agents

Every function is a CLI command with --json and stable exit codes. Shadow mode compares its decisions with Mergify's before it acts.

How a pull request lands

  1. QueuedThe rules in .mergify.yml match, or someone allowed to says @mergifyio queue.
  2. Tested togetherA draft pull request on a queue branch combines main, the changes ahead and up to a batch of new ones; your full CI runs on it.
  3. Landed, then checkedEach change lands with its expected head; afterwards the landed tree is compared with the tested one.
  4. Red? Split, not stuckA failing batch is bisected; the culprit leaves the queue with a reason, the rest lands.

Built to be trusted

A merge queue is critical infrastructure. Schlange's core is a state machine without side effects, and every claim needs evidence.

Invariants

After every simulated step: only tested trees reach main, no pull request is lost, no stale head lands.

Faults on purpose

Lost, duplicated and reordered webhooks, API errors, crashes at every side effect, an attacker with write access.

Real GitHub, side by side

A sandbox runs the same scenarios through Mergify and Schlange and compares what each one did.

Try it

git clone https://github.com/karma-works/schlange && cd schlange
tools/fetch-mergify-sources
cargo build --release -p schlange
target/release/schlange config validate .mergify.yml
target/release/schlange sim run scenarios/p1-bisection.yaml

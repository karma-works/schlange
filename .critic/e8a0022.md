## New findings

### Blocker

**N1. An agent can queue a constitution PR by editing a human's comment**
(`crates/schlange-github/src/forge.rs:1606-1650`, `unhandled_commands`).

- Reconciliation reads the 100 newest repository comments and hands each to the engine as
  `edited: false, sender = author`. It never compares `updated_at` with `created_at`.
- On GitHub, anyone with write access can edit other users' comments, and Arztagent's agent
  has write access.
- The attack: the agent edits an old non-command comment by `karma-works` into
  `@mergifyio queue` while webhooks are lost, or while `serve` is down.
- Reconciliation then runs it as karma-works' command.
- Repro C5 (webhooks dropped): the constitution PR is queued.
- Repro C6 (edit during a restart, persistent store): the `.github/workflows` PR **is merged**.
- The webhook path is correct: `control.rs:101` ignores edits. The `commands.md` sub-feature
  `once` ("edits of a command do not run it again") is therefore false for GitHub.
- Fix: skip comments with `updated_at != created_at` in `unhandled_commands`, or read
  `lastEditedAt`/`editor` (GraphQL).

**N2. A spoofed commit author keeps a pending human `queue` command alive**
(`forge.rs:455-459`, `engine.rs:685`).

- `head_by_queue` is set when the GitHub user linked to the head commit's **author email** is
  the app's bot. Commit authorship is free to set: `<id>+<slug>[bot]@users.noreply.github.com`
  maps to the app.
- The attack, repro C7:
  1. A human comments `@mergifyio queue` on a constitution PR while `KI-Review` is pending,
     so the command waits.
  2. The agent pushes `.github/workflows/evil.yml` with a commit authored as `schlange[bot]`.
  3. The command is not cancelled. The new, unreviewed head is queued under the human's name
     and **merged**.
- The fake models GitHub's email-to-login mapping through `push_as`. A sandbox should confirm
  this, but the logic does not depend on it.
- `commands.md` says this path "is not reachable" because Schlange never updates pull
  requests. It is reachable by anyone who can push.
- Fix: since Schlange never pushes to pull requests, `head_by_queue` should be `false`.
  Otherwise use the pusher from the `synchronize` webhook `sender` or the push event, never
  the commit author.

### Major

**N3. A `halt` label added during a transient 405/409 retry lands anyway (I1)**
(`forge.rs:1209-1302`).

- The in-adapter retry loop re-reads only `state`, `head` and the base tip. It does not
  re-read labels or conditions, then sends the merge again.
- Repros C1 (405) and C2 (409) fail with
  `I1: #1 landed while its conditions were false (label halt is set)`.
- This is the G1 class reintroduced by the G3 fix. The fake property test misses it because a
  fault and a label never coincide (`Then::Label` is not generated).
- Fix: on a 405/409, return to the engine (`Failed`, then Refresh, then verdict) instead of
  looping inside `land()`, or re-evaluate the conditions on the fresh read.

### Minor

- **M1. File lists are silently cut at 3000 entries** (`api.rs:392-408`, `client.rs:948`):
  30 pages of 100. `pull_files` does not compare the count with the pull request's
  `changed_files`, so a pull request with more than 3000 files can hide a constitution path
  from `-files ~= …`. GitHub caps the endpoint at 3000 itself. This should fail closed (an
  evaluation error) when the list is truncated.
- **M2. Recovery has its own gaps.** Reconciliation looks at only the 100 newest comments in
  the repository, so a command lost among more is gone. Checkbox ticks lost with their webhook
  are never recovered, because the queue's own comments are skipped.
- **M3. Condition line numbers.** `config validate` reports unsupported attributes at the
  `queue_conditions` key (`5:5`), not at the condition's own line.
- **M4. Arztagent does not change without its repository changing.** "Without changing its
  `.mergify.yml`" holds, but Arztagent's `pr-gate.yml` still needs a line for the new bot login
  (github-integration Gotchas). Two engines answering `@mergifyio` during a migration is
  unsolved, because shadow mode is missing.

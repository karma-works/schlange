# Automatic fenced adoption and recovery (design draft)

This is a proposal, not an implemented or verified protocol. It treats a cooperating, fenced writer as an operating assumption, not as proof that no historical or unfenced writer ever existed. It does not require a separate per-repository approval prompt.

## Initialization boundary

A new, genuinely empty local journal can start a versioned provisional epoch under a live local lease and GitHub fence. An existing unreadable journal, unknown local lineage or unresolved old-format state is never overwritten or silently reclassified as empty. The operator's normal deployment must stop older/noncooperating writers and pause the old queue, as in the existing adoption runbook; nothing in a repository scan proves that they were stopped. Shadow mode remains read-only.

The provisional epoch is not authority to write. Take a bounded, fenced full repository discovery and validate effective configuration (including extends), default branch, complete per-base protection requirements and app-bound check identities, PR membership/heads/fields, queue-owned refs/drafts, relevant open and terminal targets, and available command/activity records. Partial pages, permissions/errors, unstable inputs or unknown classic protection retain a visible hold for the affected scope; use a repository-wide hold where the scope cannot be determined. Recheck ingress generation, local lease and remote fence at each publication boundary and keep the existing fresh landing read/head guards. No finite GitHub read is atomic; delayed/lost webhooks, eventual consistency, remote fence ABA and the read-to-write window remain explicit residuals.

Persist epoch, selected facts, the initial action disposition and input boundary in one journal transaction before any non-lease effect. A crash between remote fence movement and that transaction leaves initialization provisional; the successor revalidates from scratch and does not infer a successful commit from the remote ref. Old binaries must be unable to write this journal or bypass the protocol; adding an ignored version field is insufficient. Session/holder identity must be unique per incarnation, not only host/PID. If downgrade exclusion cannot be enforced, this design cannot safely be activated.

## Quarantine, not invented history

Do not automatically replay old command events or uncertain side effects. For commands, use authenticated GitHub timestamps plus a persisted server-time boundary with an overlap: equal-time, edited, missing or unverifiable provenance is quarantined, never interpreted as new. Every accepted newer command still needs its original sender, unedited version, authorization and activity-log-vouched head; delayed delivery must not convert an older command into a new one. A checkbox edit lacking an authenticated editor is not replayable from REST; a later genuine action can be handled normally. Historical/closed-target commands, missing activity pages and ambiguous bot reactions need explicit conservative treatment, not just scanning currently open PRs.

The edge-action history cannot be reconstructed from current PR attributes. Do not blanket mark matching edges fired: actions such as backport and delete-head-branch must remain armed for later merge or close, and treating other matching effects as completed can silently suppress required work. Create durable, visible per-PR/rule/action unresolved-adoption holds instead. Resolve only with action-specific proof and a fresh safe redecision; do not let queue progress over an unresolved effect. A fully evaluated false edge may be armed for a later, proven false-to-true transition; unknown/evaluation-error and currently matching edge states stay held until safe reconstruction. This is conservative and may leave existing PRs held. A PR first encountered after a scan is not necessarily newly opened: require authoritative creation/event time strictly beyond the persisted boundary, plus complete membership and epoch checks, before treating it as new. Never report suppressed or ambiguous historical actions as successfully run. Unknown dispatches and uncertain action replies remain visible and are never automatically retried.

Existing queue artifacts, including foreign queue artifacts and prior closed/merged terminal events, with ambiguous ownership or in-flight work are quarantined, not automatically closed, reset, merged, or interpreted as clean. Scope by PR/base only where the discovery is complete and association is provable; otherwise hold the repository. For nonambiguous PRs, fresh queue eligibility and new queue cars can proceed once bootstrap, live lease and ingress checks pass, with the standard fresh pre-land validation. No safety claim relies on guessing prior action history.

## Cooperation and state recovery

For later same-store takeovers, persist unique epoch identity and advance trust/fence/checkpoint under holder/expiry checks. A broken predecessor, read/write/commit failure, stale holder, missing journal or unknown/downgraded schema goes to a visible hold; a later renewal cannot make it trusted merely by matching a newly written fence. Already-issued or checkpoint-only decisions, delayed replies, pending actions, cars and commands stay in doubt until their outcome and provenance can be safely resolved. Persist state+all side-effect intents atomically; do not replay non-idempotent or ambiguous operations, and apply replies plus successors transactionally. Adopted historical actions need no speculative resend.

## Evidence required before implementation is enabled

Test automatic initialization from an empty database with open PRs and exact bound check sources; queue and land fresh unambiguous work through the fake HTTP service with no operator prompt. Test existing artifacts, missing/denied/partial pages, unknown classic protection, multiple bases, source mismatch, config/extends change, pause/freeze and deleted/retargeted PRs. Inject webhook and lease changes before and after each publication/send; test delayed/out-of-order commands, boundary timestamps, head changes, edited comments/checkboxes, closed-target backports and sender permission revocation. Test matching/unknown edge baseline, armed backport/delete-head-branch through merge/close, verified false→true, PR created before but discovered after the boundary, config ABA and restart: no historical duplicate, no false success, explicit unresolved/uncertain status. Crash before/after every bootstrap, journal and send boundary; test mixed decisions, partial writes, timeouts, 2xx-before-reply and duplicate/stale responses. Test old-binary refusal or enforceably isolated old writers, same-holder ABA, remote ref reset, journal corruption and takeover on another store. A real GitHub sandbox must verify observable identity/permission semantics; simulation and fake tests remain offline.
